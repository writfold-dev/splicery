# Run-scoped edit protocol · owner proposal

## Clients and authority

Writfold provides an execution profile on its ordinary authenticated initialized stdio service. Negotiate versions and supported operations explicitly; a client cannot manufacture authority by choosing a persona. The agent starts a run with the exact plan, Weft report, repository set, finish line and request key. The host validates the subject/dependencies/report, then its own grant/predecessor/policy; return a committed RunRef before effects. Look up an uncertain intake under its original key. Worktrunk is invoked by the existing controlled adapter. Verify real repository, expected base, private contained path, branch and hook ownership. A convenient layout is playfield/RUN-017/{api,sdk}; the actual directory is a locator. Partial checkout is an observable run state.

Bind worktrees once. Capture dirty, generated or untracked *in-scope regular files* lazily when inspected, subject to explicit file policy. A worktree binding is not corpus admission. A run may query another authorized context without widening its write grant. Keep the Weft report, any KB citation explaining why, and the checked worktree selection identifying where as separate typed subjects. Preserve role and provenance.

## Logical operations

Names below describe semantics for owner negotiation. Publish a pinned owner-controlled schema, vectors and compatibility policy before calling any production method. No separate privileged transport, exposed raw path writer or shell command construction.

| Step | Required binding | Returns / failure |
|---|---|---|
| Open/inspect | principal, realm, RunRef, binding revision, worktree identity, exact file within allowed root, profile, limits | CaptureId, original blob length and digest, file locator, metadata identity, bounded bytes, authorized handle table and epoch or typed refusal |
| Select/freeze | exact capture, scope and selector/matcher profile, complete search cardinality | source spans, full-digest scoped target/capture/frozen set; preview ranges have explicit omissions |
| Prepare | exact input, source recipe bytes or typed-only IR, compiler/kernel profile, immutable alias expansion, splices and read set | host-created PreparedEditId, input and candidate digests, bounded diff, no-change or refusal. No target IO writes |
| Apply | stable request key + semantic intent digest + prepared ID; live principal, grant, procedure step, expected run head, binding revision, resource and owner generation | Claimed effect followed by confirmed receipt, proved no-effect refusal, or Unknown/partial observation under the owner ledger |
| Observe/reconcile | original effect identity, exact observation and current read grant | existing state, observation-backed transition, or unresolved unknown; never blind redispatch |
| Inspect again | exact retained postimage or new live capture | fresh scoped handles. Old handles keep historical meaning until expired; they cannot silently retarget |

Splicery provides a pure frontend and kernel. The client can parse/preview locally. The host adapter validates untrusted input and calls the same pinned kernel under its own limits. For a receipt attributing executed bytes to a *recipe*, the host independently replays the exact recipe/lowering over the authorized immutable capture and validates its read-set and IR. A matching digest supplied by the client alone does not prove derivation. If a future interface accepts IR alone, label the receipt IR-only and record its producer. Share one decision path across CLI, stdio and embedding.

## Identity and lifecycle

The [SG08 identity proposal](../qualification/sg08-identity-vectors.json) registers the six canonical domains below with fixed Writfold-compatible CBOR/SHA-256 vectors. Run `python3 -B tools/check_sg08_identity.py` for its independent calibration and adversarial checks. This is owner-review material, not an owner-published RPC schema or an available capability.

Use distinct types for RecipeDigest, CaptureDigest, PreparedEditId, CandidateDigest, RequestKey and EffectId. Canonical, length-delimited domain-separated encoding binds schema/profile versions, realm/run/repo/worktree/binding, base capture and metadata assumptions, normalized splices including replacement bytes or retained refs, resolved selection/read set, exact source/IR distinction and materializer contract. Reuse Writfold's admitted framing/canonical codec and stable intent/dispatch-stamp separation after owner review. Specify empty lists, mutation ordering, hash algorithm tags and double-encoding negatives. Session aliases and raw filesystem paths cannot substitute. A receipt binds observed before/after content, checks, outcome and effect; preserve authorized access at retrieval. A diff can be truncated and is never the content identity.

Idempotency index scopes a key to authenticated principal, realm, run and exact logical request/intent. Identical replay returns original outcome or its current reconciliation status. Same key and changed intent conflicts, including when a path cycles back to identical bytes. Keep key→intent history beyond client loss; expired prepared material gives a typed response without reopening a dispatched key. Cancel closes new admission; an already claimed external write retains its reservation until quiescence/reconciliation.

## Native materialization contract

1. Prepare in memory on immutable bytes. At apply, reserve the exact file resource, durably commit the dispatch claim under the expected head and check current grant/generation/predecessor at the effect boundary. Keep locks for the entire comparison and installation. These guarantees assume private worktrees or cooperating writers; an ordinary lock plus rename cannot fence an unrelated process doing unconditional writes. No public write capability if the declared assumption is unenforceable for that deployment.
2. Resolve path relative to a previously owned directory descriptor, disallow symlink/magic-link traversal or escape and reject nonregular targets, special files and multiply linked targets for /1. Recheck target identity, metadata and exact raw preimage under reservation. File mode/owner policy is part of the profile; preserve admitted executable bit and mode. Reject unsupported ACL/xattr, ownership or linked-file configurations rather than silently altering them. Qualify separate WSL native Linux filesystem profile; DrvFS or network mounts require their own evidence.
3. Write a same-directory exclusive temp file with controlled permissions, finish data and admitted metadata, fsync, use the platform's qualified no-clobber/replace mechanism, fsync affected directory handles (both parents after cross-directory same-filesystem rename). Preserve cleanup and evidence on failure. Atomic visibility per file, durability after required sync/observation, and durable run acknowledgement are three distinct boundaries. For create use enforced absence; for rename ensure the destination remains absent at the actual operation. Never overwrite a competing user file, auto-create parents or turn a cross-device move into copy/delete.
4. Reconcile interruption between claim, temp creation, file/directory sync, rename and receipt. Unknown records keep the original effect/reservation; qualify old process quiescence and exact discriminating evidence before resolving. A matching after-hash alone can arise independently. A multi-file change has one outcome per file; retain the applied prefix and pending work without implying rollback. Proof/test/check receipts attach to their exact content vector.
5. A failed parse, denied selection or stale precondition never performs a target write. A post-rename fsync error is an **uncertain durability outcome**, not a pre-write refusal. Diff/token logs omit ungranted original text. Bound request/reply, parser work, retained objects and preview; diagnostics never expose cross-realm content.
