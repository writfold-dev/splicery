# Rust engineering and build contract

## Small owners, narrow dependencies

Suggested workspace: splicery-domain (private validated IDs, units, captured records), splicery-syntax (lexer/parser and recipe spans), splicery-compile (resolution, typechecking and lowering), splicery-kernel (pure byte semantics and checked batches), splicery-wire (bounded versioned codecs) and splicery-cli (interface/stdio and immutable views). Begin with modules when independent crates add little; enforce these dependency directions either way. Host adapter code and privileged IO live under the Writfold owner's worktree effect boundary. Syntax/kernel must have no filesystem, Git, network, shell, Weft runtime, database, Writfold runtime, C++/Rust grammar or LSP dependency. The wire layer cannot decide authorization. Tokenization cannot authorize writes. An optional discovery tool can only propose a pinned selection.

Compile the same semantic bodies into the standalone rehearsal/preview and the owner adapter; version by artifact/source hash. Keep file assembly separate from selection resolution, normalization, codecs and dispatch. Public APIs accept checked nominal values and return typed refusals. Core arithmetic uses checked conversions into memory sizes. The validated IR has no host paths, eval, shell, loops or hidden latest reads. A normalized replacement carries a checked target range and source-linked pieces (literal or kept capture slice); a bounded copy plan can avoid copying source through model context.

| Nominal boundary | Construction / prohibited substitution |
|---|---|
| RunRef, RealmId, RepoId, WorktreeId, BindingRevision | resolved by Writfold; keep release/context and worktree namespaces distinct |
| CaptureId, CaptureDigest, GitBlobId, SelectionDigest, RecipeDigest, CandidateDigest, IntentDigest | separate namespaces/domains; no generic public String/digest bucket; literal input SHA, Git object ID and semantic digest have distinct algorithms/meaning |
| SourceByteOffset, TargetByteOffset, ByteLength, RecipeSpan, WorktreeSpan | checked bounds and units; identical integers in distinct coordinate spaces cannot be passed interchangeably |
| ReadCapture, EditTarget, WholeLine, ExactMatchSet, PreviewPage | capability and completeness distinctions; private constructors stamp image/realm/file, access and alias epoch; no From<ReadCapture> for EditTarget |
| PreparedEditId, RequestKey, EffectId, AttemptId, OwnerGeneration, AliasEpoch | request correlation, idempotency, authority and alias freshness are independent |
| CheckedBatch, PreparedEdit, AppliedReceipt, UnknownEffect | enums/state-indexed transitions; no public setter promotes a preview, boolean or untrusted wire field into authority |
| ExistingRegularFile, ExpectedAbsent, RelativeRunPath | preserve absence/existence distinction for file lifecycle and checked path segments |

Runtime evidence includes compiler-negative cases for reversed unit/identity/authority arguments; serde and FFI go via raw DTO → checked constructor → validated type, never derive an unchecked public Deserialize on sensitive wrappers. Redacted Debug/Display prevent raw blobs leaking into errors. Tooling refusal paths are typed and bounded. Document each unavoidable trusted assumption with owner and test.

## Quality gates the implementation actually enforces

- AST-count nonblank noncomment handwritten Rust lines. Warn at 250/module or 50/function; hard caps 400/module, 80/function, 250 for entrypoints, 500 per cohesive proof module. Count executable Rust hidden in macros against runtime limits. Keep cohesive semantics when splitting. An exception names exact path/symbol, owner, reason, expiry and remediation. For generated code, record generator/inputs/digest and regenerate to compare. Test counters with deliberate oversized fixtures.
- cargo fmt --all -- --check; cargo clippy --workspace --all-targets --locked --offline -- -D warnings, locked release build/tests and supported feature matrices. Deny unwrap/expect/panic/todo/unimplemented and silent truncation in shipping paths, including macro escapes. Calibrate lints against actual compiler and macro invocations. Use compile-fail tests that fail for the expected code/reason and positive controls that compile. Work through typed errors without collapsing Unknown into Failed.
- Forbid unsafe by default. Isolate any necessary OS boundary under an explicit reviewed safety contract, audit transitive unsafe separately. Check resolved Cargo graph incl renamed, build, dev, optional and target dependencies. Keep rustls-only if network machinery is separately admitted; no network client in core. License/advisory inventory pinned and offline, review denied/unknown entries, pin versions/features; no implicit deprecation or fresh upstream substitution.
- Wire refuses duplicate keys, trailing messages, unknown fields/opcodes/versions, lossy numeric conversions, mixed hash profiles and wrong handle kind. Terminal stdout stays machine-clean, diagnostics on stderr; enforce depth/frame/transfer limits before allocation, or stream under a checked allowance. Fuzz syntax/wire/paths in isolated owned workdirs; preserve minimised repros. No bare status booleans as proof.
- PRs must map edits to contract, theorem, implementation symbol, case, gate and receipt. Require independent review of proof assumptions, Verus trusted annotations, storage/refinement and capability changes. Freeze rubrics before benchmarks. A documentation change that affects semantics changes the grammar/vectors/proofs or explains why each remains valid. Keep examples, Run Watch vocabulary and limits fresh.

## Provisioning

WSL2/Linux x86_64 only. Build static musl client; proof tools and Python orchestration stay in build/test images. Adopt the sibling workflow and verify actual tool bytes. Candidate baseline Lean 4.21.0, Rust/Cargo 1.98.0 and the owner-pinned validated Verus/Z3/TLC/TLAPS combination. Record each binary and archive hash, base image digest, compiler, std library, options and dependency locks. Verify the actual musl/Verus combination and count the shipping bodies checked. A proof-oriented build with different code/config/features requires an explicit bridge.

On the operator's workstation inspect current Docker context/buildx builder, drive/filesystem identity, actual cache/target/model-volume backing, host and guest free-space floors. Discover and reuse the admitted external BuildKit location, preserve existing reserves, separate Splicery-owned caches and user state. Fail preflight before downloads/large builds when absent, mismatched or low. Never guess a drive letter, silently build on the system disk, prune shared caches or relocate the WSL disk. Online bootstrap retains signed/reviewed artifacts, then proof/build/qualification run offline with immutable inputs and bounded resources. Cold-replay in an isolated empty cache. Ship no Rust toolchain, Lean, Java, Docker, Python or credentials in the runtime image.
