# Splicery /1 · source and meaning

The normative syntax is [splicery.ebnf](splicery.ebnf). It is project EBNF. Juxtaposition sequences terms, | is choice, [] optional, {} repetition, () grouping, and quoted strings terminal symbols. UPPERCASE names are lexical terminals. The semicolon terminates a *grammar production*. Source recipes have no statement terminator. Braces delimit blocks, and prefix operators have fixed arity. One document has one file operation or edit block, or a fragment with an explicitly supplied file binding. Omitted run, file or profile in an unbound fragment is an error. There is no ambient latest file.

## Lexer

Decode recipe source as strict UTF-8. Reject BOM in recipe source, NUL outside literals, and invalid byte sequences. Never transcode the target file. Outside tokens, skip ASCII space, tab, LF and CRLF; reject lone CR. A hash starts a comment through the next line break outside literals. Keywords have ASCII identifier boundaries. Names and labels are ASCII [A-Za-z_][A-Za-z0-9_]*, case-sensitive; prohibit reserved words in NAME/HANDLE or regex group declarations. HANDLE is @ immediately followed by a name. NAT is 0 or [1-9][0-9]*, parsed exactly, range-checked before allocation. Longest match; := is one token. Dot selects a named regex group only. Bindings are spelled **@name := selector**. See the negative fixtures for the retired spelling.

- STRING uses double quotes. Decode exactly the escapes \", \\, \n, \r, \t. Other escapes, unescaped control characters and physical newlines refuse. Literal Unicode scalars become their exact UTF-8 bytes, without normalization.
- HEX uses the prefix hex immediately followed by double quotes. Body is zero or more pairs of ASCII hex digits, with no separators. Odd digits refuse. Case is immaterial; byte identity is exact.
- RX uses rx immediately followed by double quotes. Body is single-line raw regex source. A quote terminates the token. To match a quote use regex escape \x22. Backslashes are passed through. Use a pinned bounded regular engine. Profile /1 uses the Rust regex regular subset with named (?<name>...) groups, leftmost-first non-overlapping matches per body and no Unicode mode flags, inline flags, lookaround or backreferences; ASCII classes for \w, \d, \s. UTF-8 text mode only; dot matches a scalar. Reject unsupported constructs instead of changing their meaning. Pin engine/version, Unicode tables, limits and profile test vectors before SG04. Any encountered zero-width overall match refuses the entire batch before apply; present-but-empty named groups remain explicit.
- HEREDOC begins <<'TAG' followed immediately by LF or CRLF. TAG is an identifier of at most 64 ASCII bytes. End at the first physical line equal to TAG apart from its terminator. No indentation stripping, comments, interpolation or escapes. Include content terminators exactly, exclude both delimiter lines; closing delimiter may end at EOF. An empty body is valid. A colliding delimiter requires a different tag. Diagnostic coordinates are half-open byte offsets into the recipe, including its original terminators.

## Binding, selection and execution

1. Writfold resolves an explicit run, owned worktree binding and allowed relative path under its grant. Pin a captured dirty-worktree image distinct from committed git-blob/1. Text profile requires valid UTF-8, including valid boundaries for both ends of all edits and captures. Raw-byte profile accepts arbitrary bytes. Check the original image and exact candidate at the profile boundary. Paths use run repository alias plus relative segments. Reject absolute paths, empty segments, dot/dot-dot, NUL and escape via links. See the host protocol.
2. Immutable lexical bindings are introduced in source order. A name may be bound once. No forward reference or shadowing, including imports and iteration binders. The loop binding exists only inside its block. A repeated binding or unknown name is a typed error. Interactive @names resolve from a supplied exact alias table scoped to principal, session, epoch, run and capture. A loop body cannot create more iterations. Budgets apply to the whole document.
3. A file span is a zero-based [lo,hi) byte interval into one original image, including the EOF insertion point. one text and one hex enumerate all occurrences, including overlapping starts, within the selected window, and require exactly one. Empty needles refuse. one line matches a complete logical line body excluding its EOL. EOL is CRLF or LF; lone CR is content. A final unterminated nonempty line has no EOL. There is no synthetic empty line after a final EOL. For a line binding retain both body and full end. Bare line targets and keep(line) select its body. lines like and between can access its recorded terminator. within restricts to hits entirely inside the named span, without inventing line boundaries. A range uses absolute original offsets. Use # comments outside literals only.
4. between @a and @b requires distinct whole-line handles in the same image, an actual terminator on @a, and fullEnd(a) <= start(b). Its span is [fullEnd(a), start(b)). Adjacent markers select an empty range. Markers remain intact. Missing, reversed or ambiguous markers refuse.
5. line_matches enumerates matches one physical body at a time, excluding the EOL. Each member has overall span and named capture spans, sorted by original byte position. An unmatched optional group is absent, not empty; using it refuses. expect n checks the complete inventory, even if preview is truncated. A frozen set is an alternative explicitly selected during preview, bound to matcher profile, capture, exact members, groups and scope. No truncated search may mint a complete set. A live selector never re-runs during apply. expect 0 may succeed as a read; an empty edit batch returns NoChange.
6. A payload concatenates pieces in authored order. keep copies original bytes under the authorized capture. A read-only capture may supply bytes but never a destination. For /1 all keeps and targets in an edit belong to the same original file. Cross-file copying requires a later explicit information-flow contract. STRING and HEREDOC emit decoded or literal bytes. lines like @line emits each supplied string with the line's exact EOL, including the last. Reject missing EOL and CR/LF inside supplied lines. indent(prefix,payload) prefixes each nonempty logical body, including a whitespace-only body, preserving terminators exactly and never appending a synthetic line. Prefix is spaces/tabs only. Raw profile allows HEX, keep, byte ranges, one hex and literal UTF-8 payloads; reject text/line/regex/indent operations in it. Byte-target operations in the text profile must still preserve UTF-8.
7. replace, delete, before and after lower respectively to replace [lo,hi), replace [lo,hi) with empty, insert at lo, insert at hi. Copy = keep at an insertion; swap = two replacements using original captures; move = deletion plus insertion at a disjoint destination. Every operand reads the same input. Resolve and validate all commands before exposing a candidate. Sort validated splices by position. Nonempty adjacent replacements may touch. Reject overlapping nonempty ranges, coincident insertions, and insertion at either boundary or inside a nonempty replacement in the same batch. Coalesce intended same-anchor insertions in one payload. Never silently reorder conflicting edits. Compare candidate bytes; byte-identical returns NoChange without dispatch. A later stage that needs newly generated bytes must explicitly inspect the new capture.
8. Each file-set operation is one distinct effect. create needs expected absence and literal-only content (strings, blocks or hex/list thereof); rename needs exact source and absent dest within the same repository/worktree and filesystem; remove needs exact source. No overwrite, directories, symlinks, device files, file mode changes or implicit parent creation in /1. No fallback from rename to copy+delete; no cross-file transaction. Gate these capabilities independently.
9. Bounded diagnostics distinguish syntax, malformed encoding, wrong profile/kind, expired handle, missing/ambiguous selector, unexpected match count, overlap, stale target, denied, budget exceeded, unsupported, no change and unknown effect. Return original recipe span and bounded authorized nearby context when available. Failure during pure prepare produces zero writes. A diagnostic may omit content due to grant or budget.

## Limits that must be fixed before advertising a profile

Initial maxima for qualification: 256 KiB recipe, 8 MiB input, 16 MiB candidate, 4,096 splices, 4,096 matches, nesting depth 32, regex source 4 KiB, compiled automaton 1 MiB, 16 MiB retained payload material, 16 KiB preview and 128 MiB aggregate byte visits per preparation. Bound wire frames independently (1 MiB default control frames; chunk, cap and hash larger artifacts). Limits count before allocation with checked arithmetic; charge repeated visits and capture expansions. Limit hit refuses the entire preparation. Charge decoder, regex compilation/execution, diagnostics and rendering; specify a conservative regex work accounting and reject if it cannot be bounded. Changing limits versions the profile and invalidates affected evidence.
